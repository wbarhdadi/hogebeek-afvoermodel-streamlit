Hydrology engine: state boundary prototype

Two linked subcatchments: Upper routes rainfall to its outlet; Lower receives that outflow at its inlet. Each number is an outflow volume in m³ per model timestep.

Prepared model plan (immutable)

Built once per scenario from supplied preprocessed inputs: explicit subcatchment links, supplied D8 directions, and topological subcatchment order. It validates—not derives—the supplied topology. Travel times remain timestep-dependent, so each new volume gets its release lag at enqueue time. No Streamlit or file I/O crosses this boundary.

    
Runtime state (one value per run)
Mutated only by step(plan, state, rainfall_depth). It holds travel-time queues, outlet storage, and the current model timestep.

What this prototype is asking you to approve

    
Recommended decision: make the engine a dependency-light package with prepare_model(inputs) and step(plan, state, rainfall_depth)/run(plan, rainfall). The Streamlit page prepares inputs, invokes the engine, and renders returned results. Precompute static topology; retain only queue and outlet storage as timestep state.

    
This deliberately makes Lower consume Upper’s outflow during the same timestep, in topological order. A dry timestep still advances both queues and outlet storage, so water drains after rain ends.
